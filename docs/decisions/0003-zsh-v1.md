# 0003：Zsh 适配层 v1（worker 握手与降级、self-pipe、行数沿用、transient prompt、多 RES）

- 日期：2026-10-19
- 状态：提议中

## 背景

M1 把 M0 的 Zsh 原型（ADR 0001、0002）升级到 Shell 协议 v1（`docs/protocol.md`"Shell 协议 v1""Shell 侧行为变化"）。契约要求：

- 默认后端是会话常驻的 `tildy worker --parent-pid $$`，启动后先发 `HELLO`；协议版本或二进制版本与 `TILDY_PROTOCOL_VERSION`/`TILDY_VERSION` 不符时发 `BYE` 并重启，期间走一次性 `tildy render`。
- worker 未就绪、EOF、协议错误、连续启动失败时降级为 `render`；同一会话 60 秒内最多重启 3 次，超过后停留在一次性模式并记 `backend_degraded`。
- 同一 `gen` 允许多个 RES，后到的覆盖先到的；RES 带 `worker_epoch`。
- 基础提示符沿用上一周期的 `L` 行数；行数不同的结果不丢弃，存为下一周期的行数并记 `lines_mismatch`。
- `TRAPWINCH` 只写 self-pipe，空闲时也能刷新。
- `history.mode` 为 `compact` 时在 `zle-line-finish` 用 `T` 行替换提示符；退出码必须来自真实命令。
- 新增日志 `hello`、`ready`、`backend_degraded`、`transient`；丢弃原因收敛为 `stale`、`half_frame`、`eof`、`timeout`、`bad_frame`、`lines_mismatch`。

约束与输入：

- Zsh 侧仍不解析 JSON、不 `eval` 后端数据；`precmd` 与 `zle -F` 回调都在用户的同步路径上，不能阻塞。
- 任务 C 的渲染器只把用户数据里的 `%` 写成 `%%`，不转义 `$` 和反引号，依赖 Shell 永远不让后端文本经过参数展开或命令替换。
- 任务 B 的 worker（ADR 0004）：同一 gen 可能发多个 RES，包括多于一个 `fresh`（超时后迟到的结果）；RES 的 epoch 应与 HELLO 的相同；worker 自己不重启，也不保留跨进程状态。
- M0 留下的限制：空闲且没有在途请求时缩放，要等下一次按键才刷新（ADR 0002 第 4 节）；多行提示符无法显示（ADR 0001）；没有握手和 epoch。

## 决定

Zsh 侧维护一个 worker 状态机（`off` → `starting` → `ready`）：worker 在脚本加载时启动，HELLO 的协议版本和二进制版本都匹配后才接收请求；任何故障都让该 worker 退役、把当前请求改走一次性 `render`，并在下一个请求时按"60 秒内最多 3 次"的限速重启，超限后本会话只用 `render`。同一 gen 的完整帧只要 gen 是当前代次、epoch 等于 HELLO 的 epoch，就按到达顺序覆盖；缩放经加载时注册的 self-pipe 唤醒 zle；基础提示符沿用最近结果的行数；`T` 行的存在即表示 compact，在 `zle-line-finish` 和 Ctrl-C 时折叠，退出码由 `precmd` 第一条语句保存，不受任何钩子影响。

## 设计要点

### 后端与启动

- 可执行文件：`TILDY_BACKEND`，否则 `TILDY_BIN`（`tildy init zsh` 写入绝对路径，直接 `source` 时为 `PATH` 上的 `tildy`）。`TILDY_BACKEND_MODE=persistent`（默认）时以 `worker --parent-pid $$` 启动 worker，一次性请求一律 `render`；`oneshot` 时从不启动 worker。两者都找不到可执行文件时保持基础提示符，只记一次 `backend_degraded no_backend`。
- 加载时一次 `mkdir` 加一次 `mkfifo` 创建 `wake`、`req`、`resp` 三个 FIFO，`sysopen` 后立即删除。worker 子进程关闭 Shell 的其他通道 fd 后直接 `exec`，没有常驻的包装子 Shell（M0 的 persistent 有）。pid 由 `&!` 后的 `$!` 得到，EOF 即死亡信号。
- 请求写端为非阻塞，局部忽略 `SIGPIPE`；写失败或短写即判定 worker 卡死或已死。
- 加载守卫：整个文件包在一个 `if [[ -o interactive ]] && (( ! ${+_tildy_loaded} )) && zmodload ...; then ... fi` 里，没有顶层 `return`，加载总以状态 0 结束。原因见"证据"：`eval "$(tildy init zsh)"` 里的 `return` 会从 `.zshrc` 本身返回。

### worker 状态机

| 状态 | 进入 | 请求去向 | 离开 |
| --- | --- | --- | --- |
| `off` | 初始、退役后 | `render` | 下一个请求时重启（受限速）→ `starting` |
| `starting` | 启动 worker | `render`；每次请求前先 `sysread -t 0` 读一次，HELLO 已到则当场转 `ready` | HELLO 匹配 → `ready`；不匹配 → `BYE`、立即重启；超过 `TILDY_BACKEND_TIMEOUT_MS` 无 HELLO → kill，`hello_timeout` |
| `ready` | HELLO 匹配 | worker | 退役（下表） |
| 停用 | 重启超限 | `render`，直到会话结束 | — |

HELLO 必须正好 5 个字段，协议版本、epoch、pid 为十进制数字，二进制版本非空；worker 通道在 HELLO 之前收到任何其他行都是 `bad_frame`，HELLO 只接受一次。版本检查在每次发请求前用当时的 `TILDY_VERSION` 再做一次，所以升级后再次 `eval "$(tildy init zsh)"` 会让下一个提示符换用新二进制。

退役原因（`backend_degraded` 的字段）与处理：

| 原因 | 触发 | 对 worker |
| --- | --- | --- |
| `eof` | worker 退出、崩溃（读到 EOF） | 已死，关闭通道 |
| `half_frame` | 帧内又来 `RES`、`END` 的 gen 与 `RES` 不同、帧内 EOF | kill（帧内 EOF 时已死） |
| `bad_frame` | 未知标签、字段非法、HELLO 之前的其他行、RES 的 epoch 不等于 HELLO 的 epoch | kill |
| `timeout` | 请求发出后 `TILDY_BACKEND_TIMEOUT_MS` 内没有第一帧（先记 `discard gen timeout`） | kill |
| `hello_timeout` | `starting` 超时 | kill |
| `write_failed` | 非阻塞写失败或短写 | kill |
| `version_mismatch` / `protocol_mismatch` | HELLO 或之后的请求前检查 | `BYE` 后关闭写端，立即重启 |
| `mode_oneshot` | 运行中把 `TILDY_BACKEND_MODE` 改为 `oneshot` | `BYE` |
| `restart_limit` / `spawn_failed` / `no_backend` | 重启超限、FIFO 或 fork 失败、找不到可执行文件 | 不涉及在用的 worker |

- 重发：当前代次的请求已发给这个 worker、且还没有收到 `fresh` 时，退役后立即以 `render` 重发同一 gen（只收到 `partial` 也重发，`render` 的 `fresh` 会覆盖它）。在途 kill 的日志序列是 `discard gen eof` → `backend_degraded eof` → `send gen ... oneshot` → `accept gen`。
- 限速：保存窗口 `TILDY_RESTART_WINDOW_MS`（默认 60000）内的重启时间戳，已有 `TILDY_PERSISTENT_MAX_RESTARTS`（默认 3）次时停用 worker。加载时的首次启动不计；版本不符后的立即重启计入，因此 `PATH` 上的二进制与 init 时的版本永久不符时，1 + 3 次启动后停在 `render`，不会无限重启。
- 退役的通道标为 `retired`，继续读到 EOF 后关闭，迟到的帧不再处理；`TILDY_BACKEND_TIMEOUT_MS + 10 s` 仍无 EOF 时由定时器关闭。
- 计时只覆盖 worker 请求的第一帧：收到 `partial` 之后由 worker 自己按 provider 期限给出 `timeout` 槽位并发 `fresh`（ADR 0004 外层期限），Shell 再计时只会误杀健康的 worker。

### 结果的接受与多 RES

- 一次性通道的 RES gen 必须等于该进程收到的请求 gen；epoch 字段必须是数字（`render` 填 0）。worker 通道的 RES epoch 必须等于 HELLO 的 epoch，否则为 `bad_frame` 并退役该 worker。管道本来就随 worker 更换，epoch 检查是额外一层保护。
- 每个完整帧独立判定：`gen == 当前代次` 才继续，否则 `discard gen stale`。通过的帧替换待画内容、`T` 行和下一周期的行数。不比较状态，迟到的第二个 `fresh` 照样覆盖第一个；也不比较内容，与上一帧相同时多一次 `reset-prompt`（worker 已经去掉了完全相同的重复帧）。
- 暂缓（ADR 0002）期间只保留最新一份待画结果，安全时机到来时画出的是最后到达的那一份。
- `_tildy_w_got` 记录当前请求已收到的最好状态，只用于计时与退役重发，不影响显示。

### Self-pipe 缩放

- 加载时创建 `wake` FIFO，以 `sysopen -rw -o cloexec,nonblock` 在同一个 fd 上读写，随即删除路径，并用 `zle -F` 常驻注册 `_tildy_on_wake`。
- `TRAPWINCH` 只在 zle 活动时往 self-pipe 写一个字节；命令执行期间的缩放由下一个 `precmd` 的请求自然覆盖。回调读空 self-pipe，若 `COLUMNS`/`LINES` 与上一个请求不同，则递增代次并发请求，屏幕上的提示符保留到新结果到达。self-pipe 创建失败时退回 M0 的做法（trap 里直接请求）。
- 原理（ADR 0002 第 4 节）：zle 的 `poll` 数组只在一次回调分发之后重建，trap 里新注册的 fd 要等下一次分发才被 poll。self-pipe 是早已在数组里的 fd，trap 写入后 `poll` 立即返回并分发回调；回调里为新请求注册的通道 fd 随后的 `poll` 就能看到。
- 2026-10-20 修订（ADR 0002"缩放与终端重排"）：trap 里先递增代次（一轮连续缩放一次）、按新宽度截断并修正重排造成的偏移；回调不再立即请求，而是在最后一次 SIGWINCH 之后 80 ms 发一个请求。

### 行数沿用

2026-10-22 修订（0.3.4）：下面的“本周期不画”规则收窄为**正在输入时不改变高度**。安全编辑状态且 `BUFFER` 为空时，可用 ZLE `reset-prompt` 直接重绘新高度，并同步 `_tildy_lines`；输入非空则保留最新结果，记录 `defer … height_with_input`，清空后应用，代次变化后丢弃。首次启动、修改空行与重新加载不再需要额外回车。补全、增量搜索、续行等状态仍须暂缓；ACK 仍只在实际显示后发送。PTY 覆盖首次三行提示符、3→2→3→2 重载、保留上方输出和已输入命令、延迟 ACK、instant 缓存与缩放。

- `_tildy_next_lines` 为当前代次最近一个结果的 `L` 行数（包括本周期画不出来的那个），首个提示符为 1。`precmd` 放基础提示符时取 `TILDY_BASE_PROMPT` 的最后一行，在上面补 n−1 个空行。
- 结果的行数不等于当前提示符的行数时不画，记 `discard gen lines_mismatch`，行数留给下一周期。编辑期间提示符高度不变（ADR 0002 的不变量）。
- 结果是一行时 `_tildy_next_lines` 回到 1，所以从两行配置改回一行，同样只损失一个周期。

### transient prompt

- Shell 不读配置：结果里有 `T` 行就表示 `history.mode` 为 `compact`，后端在其他模式下不发 `T` 行。`T` 行与 `L` 行一样可重复，Shell 用换行拼接（2026-10-20 起：`add_newline` 打开时 transient 的第一行为空行，折叠后的历史里命令块之间仍有空行，与 p10k 一致；`history.add_newline: false` 关掉）。每个通过的结果都更新 `T` 文本以及它所属的提示周期（`precmd` 计数），只使用本周期的结果，上一周期的 `T` 不会用到新的一行上。
- 回车（包括 isearch 中回车）：`zle-line-finish` 钩子在 `CONTEXT == start` 时（续行 PS2 不折叠）通过 `_tildy_set_prompt` 写入 `T` 文本（与普通结果同样不经过替换），`zle .reset-prompt`，记 `transient gen`。两行提示符折叠为一行。
- Ctrl-C：放弃当前行既不触发 `zle-line-finish`，也不运行 `precmd`。`TRAPINT` 只在 zle 空闲于顶层时折叠：`CONTEXT == start`、`WIDGET == LASTWIDGET`（没有嵌套在仍在执行的 widget 里）、不在补全或 isearch 中。折叠后 `zle -R` 刷出，再把 `PROMPT`/`RPROMPT` 恢复成完整提示符（不重绘），zle 放弃该行后在新行画出完整提示符；记 `transient gen int`。trap 返回 `128 + 信号号`，与没有 trap 时一样中断当前行或命令；已有 `TRAPINT` 函数时串联调用它，已有列表式 `trap '...' INT` 时不安装（定义函数会覆盖它），记 `hook_skipped int list_trap`。
- 退出码：折叠发生在命令执行之前（`zle-line-finish`），或者根本没有命令（Ctrl-C）。`precmd` 的第一条语句保存 `$?`；`sched` 回调把进入时的 `$?` 原样返回；`zle -F` 回调在 zle 内部运行，不改变 `$?`。
- 2026-10-25 起，接受纯空白输入后，下一提示符请求的退出码归零，以清除错误标记和颜色；真实 `$?` 与已经打印的失败摘要保留。`zle-line-finish` 在 compact/full 分流之前记录空白输入，`preexec` 在实际执行命令时清除标记，`precmd` 消费并清除它。不能仅以未触发 `preexec` 判断空输入，因为语法错误同样不触发它。

### 后端文本不经过替换

沿用 ADR 0001：写入时按当时的选项选择写法，`prompt_subst` 打开时写 `PROMPT='${_tildy_ps_left}'`，参数值不会再被扫描 `$(...)`、反引号或 `${...}`；`prompt_bang` 打开时把 `!` 写成 `!!`。`T` 行与 Ctrl-C 的折叠走同一个函数。M1 里这一条从纵深防御变成了安全前提，因为渲染器不转义 `$` 和反引号。

### 其他

- `ready gen` 在 `precmd` 的同步部分结束时记录：基础提示符已就位，请求已发出，Tildy 不再占用同步路径。
- `chpwd` 在命令执行期间只递增代次（随后的 `precmd` 发请求），所以一条 `cd` 让代次加 2、只发一个请求；在 widget 里 `cd`（zle 活动）时立即放基础提示符并请求。
- 第一个提示符通常走 `render`：worker 在加载时启动，但 HELLO 一般在第一个 `precmd` 之后 0.3–3 ms 才到。基础提示符照常立即显示，代价只是异步路径上多一个 `render` 进程。

各 M1 场景的观测（默认运行的备注）：

- `worker_degrade_to_oneshot`：kill 空闲 worker 后下一个提示符由 `render` 画出（`recv` 的 epoch 为 0），再下一个由重启的 worker 服务；kill 在途请求时 `discard eof` 后同 gen 以 `render` 重发并画出。
- `version_mismatch_restart`：A 阶段 `hello 9.9.9-bogus` → `bye` → 重启 → `hello 0.1.0-m1`，后续结果带新 epoch；B 阶段每个 worker 都不符，4 次启动、4 个 BYE 后 `restart_limit`，之后只走 `render`，没有残留 worker。真实二进制下 `TILDY_VERSION=0.0.0-bogus` 同样停在 `restart_limit`。
- `transient_prompt`：回车、Ctrl-C、isearch 接受都折叠为 `❯ `；`false` 之后 `echo rc=$?` 输出 `rc=1`，假后端 trace 中下一个 REQ 的 `last_exit` 为 1；两行提示符折叠为一行。
- `multi_line_result`：第一周期 `discard 1 lines_mismatch` 并保留基础提示符，第二周期画出两行，输入与光标正确。
- `resize_idle`：不按键，缩放后 22–25 ms 画出新结果（一次性，含进程启动）；`resize_idle_worker`：假后端 4 ms，真实二进制 2–11 ms。
- `fast_cd_burst`：一次输入 10 条 `cd`，10 个请求、代次 +20，旧结果 9 次 `discard stale`，只画出最后的 dirB，zsh 下只剩 worker 一个子进程。
- `terminal_kill_no_orphan`：对 zsh 发 SIGKILL、SIGHUP 后，假后端 worker 在 24–27 ms 内退出，真实 worker 在 6–33 ms 内退出（都是读到 stdin EOF，早于 2 秒一次的父进程检查）。
- `nested_shell`：内层 zsh 有自己的 worker，`exit` 后随即退出，外层 worker 不受影响。
- `partial_then_fresh`：同一 gen 的 `partial`、914 ms 后的 `fresh`、再 1.5 s 后的第二个 `fresh` 依次画出，后到的覆盖先到的，输入的行和光标不变。
- `worker_epoch_mismatch`：RES epoch 424242、HELLO epoch 777 → `discard 2 bad_frame`、`backend_degraded bad_frame`，worker 被 kill，同 gen 以 `render` 画出。
- `real_slow_git_refresh`（真实二进制，`PATH` 前置一个先 sleep 0.4 s 的 `git`）：partial 立即画出，fresh 在逐字输入的第 400–450 ms 到达，行内容与光标正确；补全菜单打开时 fresh 到达记 `defer widget=expand-or-complete`（fzf 下为 `widget=fzf-completion`），离开菜单后 `apply_deferred`。syntax-highlighting 保持高亮，autosuggestions 保持建议后缀。

### PROMPT_SUBST 与真实渲染器

- 真实渲染器对目录 `x$(touch /tmp/tildy-pwned-1)` 输出 `L	%B%F{blue}…/x$(touch /tmp/tildy-pwned-1)%f%b ❯ `（`tildy render` 手动喂 REQ），确认 `$(...)` 与反引号原样进入帧。
- `prompt_subst_injection`（`python3 tests/pty/run.py --real --scenario prompt_subst_injection`）：`setopt prompt_subst prompt_bang` 下依次进入 `x$(touch PWNED1)`、`` y`touch PWNED2` ``、`x$(touch /tmp/tildy-pwned-<pid>)`（嵌套路径），每个目录再完整走一个周期（含 transient 折叠）。提示符原样显示，例如 `…/home0/x$(touch PWNED1) ❯`；临时目录下没有 `PWNED*`，`/tmp/tildy-pwned-<pid>` 不存在。
- 反证：把 `_tildy_set_prompt` 的 `prompt_subst` 分支改成 `if false`（内容直接放进 `PROMPT`）后同一场景失败，提示符显示为 `[g4 x]`，即命令替换被执行。

### 加载方式

- `eval` 里的 `return`：文件 `rc.zsh` 内容为 `print before; eval 'print "in eval"; return 0'; print after`，`zsh -f -c 'source rc.zsh'` 只输出 `before`、`in eval`，`after` 没有执行。改为加载守卫后，在 `.zshrc` 里连续两次 `eval "$(cat shell/zsh/tildy.zsh)"` 再 `print AFTER_SECOND_LOAD`，`zsh -i` 输出 `AFTER_SECOND_LOAD`，`$?` 为 0。harness `source_twice` 增加了对应检查（重新 `source` 一个加载 Tildy 的 rc 文件，其后的行必须执行）。
- `eval` 一次解析整个字符串：`zsh -f -c 'alias kill="print ALIASED"; eval "setopt no_aliases; f() { kill -0 \$\$ }"; functions f'` 显示 `print ALIASED -0 $$`；同样内容用 `source` 加载时 `f` 保持 `kill -0 $$`。因此 Tildy 脚本无法在自身内部关闭别名展开。以 `zsh -f -i` 加载后对比全部 `_tildy_*` 函数体：oh-my-zsh `common-aliases` 的全局别名（`H`、`T`、`G`、`L` 等）不改变任何函数体（`case` 模式不做别名展开）；普通别名 `alias kill='kill -9'` 会把三处 `kill -TERM` 变成 `kill -9 -TERM`。

### Ctrl-C 的 `$?`

独立 ZDOTDIR 下依次输入 `false`、`abc`、Ctrl-C、`echo RC=$?`：不加载 Tildy 与加载 Tildy（假后端，带 `T` 行）都输出 `RC=130`。

## 后果

- 正面影响：
  - `eval "$(tildy init zsh)"` 一行即可使用 worker；worker 崩溃、卡死、版本不符、协议错误都不会让提示符消失，最坏情况是本会话退回 M0 的一次性模式。
  - 旧 worker 的回包在结构上无法画出：通道随 worker 更换，epoch 再校验一次。
  - 空闲缩放不再等按键；多行提示符可以显示；transient 不碰 `$?`。
  - 多 RES 的处理不依赖状态顺序，worker 将来增加新的中间帧也不需要改 Shell。
- 负面影响与代价：
  - 每个交互 Shell 多一个常驻 worker 进程；第一个提示符通常多一个 `render` 进程。
  - 定时器仍是 `zsh/sched`，粒度 1 秒：HELLO 超时与第一帧超时在 `[T, T+1s)` 内触发。
  - 行数变化后的第一个周期只显示基础提示符。
  - 用户已有列表式 `trap ... INT`/`WINCH` 时，Ctrl-C 不折叠、空闲缩放不刷新。
  - 每个结果都重绘一次，同内容的帧也一样。
- 需要后续处理的问题：
  - 别名：`eval` 在执行前解析整段脚本，用户的普通别名（如 `alias kill='kill -9'`）会改写 Tildy 的函数体。解决办法是让 `tildy init zsh` 输出一个先关闭别名再加载的包装（需要改 `src/cli/init.rs`，主控持有），或者在脚本里给命令词加 `\`/`builtin` 前缀（M1 集成时决定）。
  - `prompt_subst` 的写法在写入 `PROMPT` 时决定。如果某个 widget 在编辑中途打开 `prompt_subst`，在 Tildy 下一次写入之前，其他原因引起的重绘（缩放、`clear-screen`、其他插件的 `reset-prompt`）会对后端文本做替换。可以在 `zle-line-pre-redraw` 里检测选项变化并重写（M2）。
  - HELLO 之前的请求可以直接排队给 worker，省掉第一个提示符的 `render`；前提是定下 HELLO 不匹配时排队请求的处理（M2，需同步契约）。
  - 契约需要写明：`T` 行存在即 compact；重启限速不计首次启动、计入版本不符后的重启；worker 请求只对第一帧计时；HELLO 的超时值。
  - 请求里的 `env` 只是缓存修订，provider 读的是 worker 自己的环境（ADR 0004）；会话中途改变 `VIRTUAL_ENV` 等变量不会反映到提示符，需要在契约里决定由谁负责。

### 2026-10-19（M1b 任务 C）：REQ 增加 `jobs`，`env` 改为键值对

只改请求字段，状态机与其余行为不变。

- `REQ` 由 9 个字段变为 10 个：第 9 个 `env`，第 10 个 `jobs`（`${#jobstates}`，整数）。
