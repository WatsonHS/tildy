# 0011：配置锁按实际文件定位，等待有期限

- 日期：2026-10-22
- 状态：已接受（已实现于 M4 本地开发，基于 0.3.5）
- 更新：[ADR 0007](0007-config-transactions.md) 的锁策略

## 问题

M2 已在历史目录 `.lock` 上使用 `flock`，且 `apply`、`rollback` 在锁内重读修订；已有八进程单赢家测试。原 M4 计划的“缺写锁”不符合代码现状。

实际缺口有两个：锁等待没有期限；相同配置配上不同 `XDG_STATE_HOME` 时会使用不同锁，修订比较与替换可能并发通过。直接配置路径、文件符号链接和父目录符号链接应得到相同的写入保护。

## 决定

事务先解析配置符号链接，规范化父目录，在实际目标旁取得 `<文件名>.lock`，随后取得原有历史目录 `.lock`。所有写入按相同顺序取锁；锁内读取和替换使用同一个已解析目标。历史锁继续保护历史编号、保存和修剪，也与使用相同历史目录的旧版写入保持互斥。

两次获取共用从事务取锁开始计算的 2 秒等待预算，使用 `LOCK_NB` 和最多 10 ms 间隔重试。预算仅限制锁竞争等待，不给磁盘 I/O 提供实时期限。拿到锁后才写持有者 PID。锁文件保持原 inode，不删除；关闭描述符或进程退出即释放内核锁，因此留下的 PID 不表示锁仍被占用。

锁文件拒绝符号链接、非普通文件、硬链接及非空非 PID 内容，避免把路径碰撞当作可覆盖的锁文件。新文件权限为 0600；同目录持久锁可能出现在 dotfiles 仓库中，可由用户按需忽略。

## CLI 兼容

保持 API v1 的错误枚举和 envelope 不变。超时使用 `environment_unavailable`（退出码 4），`message` 以 `config locked` 开头，包含锁路径及读取到的 PID；PID 不可读或旧锁未记录时明确写 unavailable。PID 只是诊断快照，不能用于自动杀进程。`hint` 说明文件未改变、等待其他写入者并重试、不要删除锁文件。原 M4 草案的新增 `locked` 错误码不采用。

`config apply`（包括 `--force`）、`config rollback`、`theme` 及兼容别名 `configure` 共用此实现。`palette`、`preset` 目前只有 list/show，不存在独立写入路径；主题和调色板的应用通过 `theme` 或配置事务完成。

## 后果与边界

锁协调遵守同一协议的 Tildy 写入者。手工编辑器、外部重定向符号链接和删除锁文件不受此协议约束；事务固定解析时的目标。旧版若同时使用不同历史目录，也不认识新增目标锁，不能声称新旧混用时跨状态目录安全。
