# 架构决策记录（ADR）

每个会影响协议、数据格式、依赖选择或范围的决定，都用一份 ADR 记录背景、决定、证据和后果。ADR 一经接受即不再改写结论；被推翻时新增一份 ADR，并在旧记录的状态中指向它。

## 命名约定

- 文件名为 `NNNN-slug.md`：`NNNN` 为四位十进制编号，从 `0001` 开始，按创建顺序递增，不复用编号。
- `slug` 为小写英文短语，单词之间用连字符，例如 `0003-config-revision.md`。
- 编号一旦分配即固定，即使对应决定被放弃，也保留该编号并把状态改为「已废弃」。

## 状态取值

`提议中` → `已接受` → （可选）`已被 NNNN 取代` 或 `已废弃`。

## 模板

复制下面的内容到 `docs/decisions/NNNN-slug.md` 后填写。

```markdown
# NNNN：标题

- 日期：YYYY-MM-DD
- 状态：提议中 | 已接受 | 已被 NNNN 取代 | 已废弃

## 背景

说明需要做决定的问题、约束与影响范围。只写事实和约束，不写结论。

## 决定

用一到三句话写出决定本身，使用肯定句。

## 证据

列出支撑决定的证据：实验命令与输出摘要、测量数据及样本量、官方文档链接、被排除方案的理由。
每条证据注明来源与采集日期；无法复现的数据不作为证据。

## 后果

- 正面影响：
- 负面影响与代价：
- 需要后续处理的问题（对应的里程碑或任务）：
```

## 写作要求

- 标题、正文使用中文；代码、命令、字段名保持原文。
- 证据部分必须可复现：给出命令或文件路径，而不是只给结论。
- 「决定」与「后果」分开写，不把后果写成决定。
